= 責任あるAIの原則
include::../_attributes.adoc[]

[cols="1,3", options="header"]
|===
| 原則 | 満たすための具体

| 透明性 | 評価基準、使用データ、モデルの挙動、限界と制限事項を開示する
| 公平性 | データとモデルのバイアスを検出し、偏りを測定する
| 説明可能性 | 個々の予測がなぜその値になったかを示す
| プライバシー | 学習データから個人識別情報を除去する
| 安全性・セキュリティ | 有害な出力と不正利用を抑止する
|===

- 評価プロセスに対して「公平性と信頼をどう築くか」→ 透明性の確保。評価基準やモデルの限界が開示されて初めて、利用者と監査者が判断根拠を確認できる。

== ヒューマンインザループ

[cols="1,3", options="header"]
|===
| 要素 | 中身

| 判定に使う仕組み | 問い合わせ分類モデル、感情分析、生成結果の信頼度評価、ポリシーチェック
| レビューへ回すトリガー | 低信頼スコア、強い不満表現、クレーム分類、ネガティブ感情
| 人が調整すること | 文脈、感情、謝罪表現、補償の可否
|===

- 誤判定が起こりやすい領域: 皮肉、曖昧な言い回し、文化的ニュアンス。技術ではなく運用プロセスで抑える。
- HITL は、人間のレビュー担当者が出力を確認し、必要に応じて修正・承認する工程。
- 誤回答の影響が大きい領域（カスタマーサポート、医療、法務、コンプライアンス）では、人間の判断を品質保証の最後の関門に置く。
- 設計の要点は、全件ではなくリスクの高いものだけを人に回すこと。自動化の効率を保ったまま品質を担保できる。
- 例: 複雑な感情表現や遠回しな不満を含むクレームは、モデルが文脈を誤読して事務的すぎる返信を生成しうる。こうした返信だけ送信前に担当者が確認・修正する。

原因別の対策。

[cols="1,1", options="header"]
|===
| 原因 | 対策

| ニュアンスの誤読 | ヒューマンインザループ
| 知識のカットオフ | RAG
| 情報源を固定したい | グラウンディング
|===
